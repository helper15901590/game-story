# **我的故事istory：产品需求文档 (PRD) V4.0**

## 1. 产品概述

### 1.0. 公司定位
我的故事istory 是一款无屏故事机，支持家长、老师与孩子创作并收听故事/播客。

### 1.1. 产品版本
- **ISTORY mini（3-5岁）**：旋钮切换多个不同小故事，无分支，适合幼儿自由切换、语言启蒙。
- **ISTORY（6-12岁）**：多分支主线，结合创作与探索玩法，适合大龄儿童自主决策。

## 2. 核心功能

### 2.1 ISTORY 功能列表（6-12 岁）

#### 主要功能

1. **分支故事 - 分支选择：旋转+按下**：跳转到对应主线 M，播放时灯熄灭。
2. **线性播放 - 当前 M 无选项**：自动跳到下一条主线 M，播放时灯熄灭。
3. **跳过当前 - 长按插播 ≥1s**：跳过当前 M 剩余部分，进入下一个决策点，播放时灯熄灭，播放系统音效 1007。

#### 辅助功能

4. **暂停/续播 - 短按旋钮**：切换播放 / 暂停，暂停时白色呼吸灯。
5. **主动关机 - 长按旋钮3秒**：关机，灯灭，播放系统音效 1002（关机音效）。
6. **自动关机 - 暂停 30 分钟无操作**：自动关机，灯灭，无音效（防止打扰休息）。
7. **自动关机 - 选项等待或待机 3 分钟无操作**：自动关机，灯灭，无音效（防止打扰休息）。
8. **电量提示 - 电量≤20%时**：红灯闪烁3次提醒（一次性），无音效（防止打断主音频播放无法续播）。
9. **没电关机 - 电量≤10%时**：闪红灯3次，然后播放没电提示音效直接关机，红灯闪烁3次后灯灭，播放系统音效 1008（电量≤10%音效）。
10. **没电开机 - 没电时尝试开机**：无法开机，播放没电音效，灯灭，播放系统音效 1008。

#### 增值功能

11. **小夜灯 - 关机状态短按旋钮（白→熄灭）或短按灯泡键（黄灯）**：控制夜灯，3 小时自动熄灭。


### 2.2 ISTORY mini 功能列表（3-5 岁）

#### 主要功能

1. **随机播放 - 插卡成功**：随机播放文件夹中的第一条故事，灯熄灭，播放系统音效 2005。
2. **旋转切换 - 按顺序切换（≥500 ms）**：顺序切换上一条/下一条故事，亮一下再灭（视觉提示）。

#### 辅助功能

3. **暂停/续播 - 短按旋钮**：暂停/继续，暂停时白色呼吸灯。
4. **主动关机 - 长按旋钮3秒**：关机，灯灭，播放系统音效 2002（关机音效）。
5. **自动关机 - 暂停 30 分钟无操作**：自动关机，灯灭，无音效（防止打扰休息）。
6. **自动关机 - 未插卡待机 3 分钟无操作**：自动关机，灯灭，无音效（防止打扰休息）。
7. **电量提示 - 电量≤20%时**：红灯闪烁3次提醒（一次性），无音效。
8. **没电关机 - 电量≤10%时**：闪红灯3次，然后播放没电提示音效直接关机，红灯闪烁3次后灯灭，播放系统音效 2007（电量≤10%音效）。
9. **没电开机 - 没电时尝试开机**：无法开机，播放没电音效，灯灭，播放系统音效 2007。

#### 增值功能

10. **小夜灯 - 关机状态控制白灯/熄灭**：3 小时自动熄灭。

## 4. 产品迭代路线图 (Roadmap)

### 第二阶段

**Wi‑Fi**：支持Wi-Fi内容更新。

**每日播客**：待机状态下短按灯泡键进入，旋转旋钮切换播客节目。Wi-Fi推送新闻、科普、故事、音乐等音频内容。初期暂不支持收藏功能。

**开放式互动故事平台**：小程序选择故事并下载，下载时插入NFC卡片进行烧录。支持创作、分享、出售互动型故事（2:8分成）。

### 第三阶段

**屏幕与动画**：新增小型显示屏，显示故事标题、进度、选项高亮等。

### 第四阶段

**智能语音互动**：集成语音识别模块，支持语音点播、简单问答。

**耳机输出**：支持3.5mm耳机输出。

**NFC卡记忆功能**：通过插拔卡触位按钮实现故事进度保存和恢复。

*注：各阶段功能应保持向下兼容，不影响第一阶段的核心体验。*

## 附录：我的故事istory编码规则技术规范

### 0. 制作流程总览

1. **撰写剧情脚本**：按 `M-O-M-M-E` 的层级结构完成文本剧情（E视为M）。
2. **规划音频文件**：确认 TF 卡文件夹和每个 M 节点下的音频编号。
3. **NFC 芯片写入**：先启用密码，再写入故事编号、主音频数量及主线跳转数据。
4. **拷贝 TF 音频**：将故事文件夹和系统音频拷贝至 TF 卡。
5. **整机联调验证**：插入 TF 卡并靠近 NFC 芯片，验证音频跳转与剧终行为。

### 1. 文本剧情模块

#### 1.1. 核心标记定义与编码规则

| 标记类型 | 标记格式 | 含义说明 |
|---------|---------|---------|
| **M** | M1, M2, M3... | 主线剧情节点 |
| **O** | O1-1, O1-2, O1-3... | 分支选项（00-03个）。某个主线 Mx 下的选项统一编码为 Ox-1、Ox-2、Ox-3，例如：M1 下的选项为 O1-1、O1-2、O1-3。 |
| **E** | E1, E2, E3... | 结局音频（视为M类，在NFC中以`00 00 00 00`标记） |

#### 1.2. 故事结构

```
M1 (主线剧情1)
    ├── O1-1 → 跳转到 M2 → M5 (主跳主/E结局)
    ├── O1-2 → 跳转到 M3 → M5 (主跳主/E结局)
    └── O1-3 → 跳转到 M4 → M5 (主跳主/E结局)

```

### 2. NFC编码模块

#### 2.1. 硬件参数

- **芯片型号**：NTAG216（ISO 14443-3A）
- **存储容量**：国产芯片868字节 / 进口芯片888字节
- **扇区地址**：十六进制格式

#### 2.2. 写入流程概览

1. **读取芯片与记录 UID**：验证当前芯片型号是否为 NTAG216。
2. **设置/启用密码**：依据 2.7 节的命令写入 E3-E6 扇区。
3. **写入故事元数据**：在扇区 04 写入故事编号与主音频数量（参见 2.5 节），确保 TF 卡文件夹命名与数量校验一致。
4. **写入主线节点数据**：从扇区 05 开始依次写入每个 M 节点的跳转配置（参见 2.6 节），并即时核对跳转逻辑。
5. **按需关闭或保持密码**：若需开放读写，执行 2.7 节的“关闭密码”流程；否则保留密码并记录给量产或售后团队。

#### 2.3. 工具与命令操作

**工具**：NFC TOOLS PRO（Android 应用）

**操作步骤**：
1. 打开 NFC TOOLS PRO。
2. 进入 **其他** → **先进的 NFC 命令**。
3. 点击 **放大镜** 图标，选择 **TAG TYPE2（ISO14443-3A）**。
4. 选择 **Write4bytes**（写入 4 字节）。
5. 根据 2.5、2.6、2.7 节的内容，统一写入命令。

**写入格式**：
- 格式：`A2:XX:BB:BB:BB:BB`
  - `A2`：写入命令（固定不变）
  - `XX`：写入块编号（十六进制，可变，如 `04` 表示扇区 04）
  - `BB:BB:BB:BB`：当前扇区的第 1、2、3、4 个块（Block）的数值（十六进制）
- **连续写入**：可以连续写入不同的块，用英文字符 `,` 间隔
  - 示例：`A2:04:10:01:0A:05,A2:05:03:02:03:04`

**命令说明**：
- `A2`：写入命令（用于写入数据到指定扇区）
- `1B`：密码验证命令（用于验证密码后执行后续操作）


#### 2.4. 扇区布局

| 扇区地址 | 对应M节点 | 用途 |
|---------|---------|------|
| `04` | - | 故事元数据区（故事编号、主音频数量） |
| `05+` | M1+ | 主线故事数据区（每个M节点占用1个扇区，4个块/Block） |
| `E3-E6` | - | 密码区和验证码区 |

#### 2.5. 扇区04：故事元数据区

##### 2.5.1 ISTORY（6-12岁）扇区04编码规则

| 块（Block） | 字段 | 格式 | 说明 |
|------|------|------|------|
| 1 | 故事编号高位 | 十进制 | 仅用于与低位做**前后拼接**，不做加减或进位计算，如：10 |
| 2 | 故事编号低位 | 十进制 | 仅用于与高位做**前后拼接**，不做加减或进位计算，如：01 |
| 3 | M主音频数量 | 十六进制 | M主音频数量（十六进制00-FF），如：20表示32条主音频（含E类结局音频） |
| 4 | 默认值 | 十六进制 | 默认00（无任何意义） |

**示例**：
- NFC中故事编号：高位`10` + 低位`01` → 设备按字符串前后拼接为 `1001`
- TF卡中文件夹名：在前面再补一位固定前缀`0`，最终为 `01001`，用于实际的故事文件夹匹配
- 主音频数量：20 = 十六进制`14`，写入块3；块4固定为`00`


##### 2.5.2 ISTORY mini（3-5岁）扇区04编码规则

| 块（Block） | 字段 | 格式 | 说明 |
|------|------|------|------|
| 1 | 音频数量高位 | 十进制 | 音频数量高位（十进制，与block2物理组合），如：00 |
| 2 | 音频数量低位 | 十进制 | 音频数量低位（十进制，与block1物理组合），如：52 |
| 3 | 默认值 | 十六进制 | 默认00（无任何意义） |
| 4 | 默认值 | 十六进制 | 默认00（无任何意义） |


#### 2.6. 扇区05+：主线故事数据区

| 块（Block） | 字段 | 取值范围 | 说明 |
|------|------|---------|------|
| 1 | M1的O类音频数量 | `00-03` | M1的O类音频数量（00-03），如：03；若为00，则代表没有选项 |
| 2 | O1跳转M音频编号 | `00-FF` | O1跳转M音频编号（00-FF），如：02（M2）；若block1为00，则写跳转主音频编号（00-FF）；若block1和此都为00时，则表示结束音频 |
| 3 | O2跳转M音频编号 | `00-FF` | O2跳转M音频编号，如：03（M3） |
| 4 | O3跳转M音频编号 | `00-FF` | O3跳转M音频编号，如：04（M4） |

**M节点编号映射**：M编号 = 十六进制值（M1=`01`, M2=`02`, M10=`0A`, M11=`0B`, M17=`11`...）

**示例**：
- **M1节点（扇区05，3个选项）**：`03 02 03 04` → 3个选项，分别跳转到M2、M3、M4
- **M2节点（扇区06，2个选项）**：`02 05 01 00` → 2个选项，分别跳转到M5、M1

#### 2.7. 扇区E3-E6：密码与验码区

| 扇区地址 | 功能 | 数据内容（十六进制） | 说明 |
|---------|------|------------------|------|
| `E3` | 密码命令 | `04 00 00 00` | 密码操作命令字（最后 1 字节 `00`=启用密码、`FF`=关闭密码） |
| `E4` | 密码错误机制 | `00 05 00 00` | 试错次数限制（示例为 5 次） |
| `E5` | 密码保存区域 | ISTORY: `0x31 0x35 0x39 0x30`；ISTORY mini: `0x30 0x39 0x35 0x31` | NFC 密码（ASCII 编码） |
| `E6` | 验证码区域 | `0x32 0x32 0x00 0x00` | 验证码：22（ASCII 编码） |

**ISTORY（6-12岁）写入密码命令**：
```
A2:E3:04:00:00:00,A2:E4:00:05:00:00,A2:E5:31:35:39:30,A2:E6:32:32:00:00
```
**ISTORY（6-12岁）关闭密码命令**：
```
1B:31:35:39:30,A2:E3:04:00:00:FF,A2:E4:00:05:00:00,A2:E5:00:00:00:00,A2:E6:00:00:00:00
```
- 首先使用 `1B` 命令验证当前密码（1590）。
- 依次写入 E3（关闭密码，最后字节改为 `FF`）、E4、E5、E6，将密码与验证码清空。


**ISTORY mini（3-5岁）写入密码命令**：
```
A2:E3:04:00:00:00,A2:E4:00:05:00:00,A2:E5:30:39:35:31,A2:E6:32:32:00:00
```
**ISTORY mini（3-5岁）关闭密码命令**：
```
1B:30:39:35:31,A2:E3:04:00:00:FF,A2:E4:00:05:00:00,A2:E5:00:00:00:00,A2:E6:00:00:00:00
```
- 首先使用 `1B` 命令验证当前密码（0951）。
- 依次写入 E3（关闭密码，最后字节改为 `FF`）、E4、E5、E6，将密码与验证码清空。

### 附录 A：TF音频命名模块

**音频格式要求**：MP3/WAV（推荐MP3），8kHz-44.1kHz采样率，单声道，8kbps-320kbps码率

#### A.1 系统文件夹命名规则

- **模式一/模式二通用**：`SYSTM`（全大写），存放系统音效相关文件

#### A.2 故事文件夹命名

- **模式一/模式二通用**：00000-09999，首位固定为`0`，后4位与NFC扇区04中的故事编号（高位+低位拼接）一一对应）

#### A.3 故事音频文件命名规则

- **音频文件（ISTORY mini，3-5岁）**：`0001`-`9999`（4位十进制数字），每张卡一个文件夹，按文件顺序供旋钮切换

| 音频类型 | 命名格式 | 编号规则 | 示例 |
|---------|---------|---------|------|
| **M类主音频 / E类结局音频** | 4位数字 | 前3位为M节点编号 + 最后1位固定`0` | M1 → `0010.mp3`（若为结局则在NFC中以`00 00 00 00`标记为E类） |
| **O类选项音频** | 4位数字 | M编号前3位 + 第四位`1-3` | M1的O1 → `0011.mp3`，O2 → `0012.mp3` |

**编号对应关系（ISTORY）**：
- M/E类：E类结束音频在TF卡中与所属M节点的主音频共用同一命名规则（即"E视为M"）
- O类：O1→1, O2→2, O3→3

**文件组织（ISTORY）**：按M节点分组，顺序为 M类主音频 → O类选项音频（按编号）

**音频命名（ISTORY mini）**：文件夹内音频建议使用4位顺序编号 `0001`-`9999`，按文件顺序播放。

**示例**（故事文件夹`01001/`）：
- M1节点（3个选项）：`0010, 0011, 0012, 0013`
- M2节点（2个选项）：`0020, 0021, 0022`

## 开发问答

本章节用于说明产品开发过程中功能增减的背景和原因，帮助开发团队理解设计决策。

### Q1: 为什么删除了K类彩蛋插播功能？

**原因**：
- 简化交互逻辑，降低使用复杂度
- 减少内容制作成本，无需制作K类音频
- 插播按键改为长按跳过主音频功能
- 保留核心M/O分支剧情功能

---

### Q2: 为什么ISTORY mini和ISTORY使用不同的NFC编码规则？

**原因**：
- **ISTORY**：支持分支剧情（M/O结构），块3存储主音频数量（十六进制，最大255个）
- **ISTORY mini**：仅做文件校验，块1和块2物理组合存储音频数量（十进制），无需故事编号

---

### Q3: 为什么电量提示分为两个等级（≤20%和≤10%）？

**原因**：
- **≤20%**：红灯闪烁3次（一次性），无音效（避免打断主音频播放而无法续播）
- **≤10%**：红灯闪烁3次后播放没电提示音效并直接关机
- 分级提醒，避免频繁打扰，确保及时提醒

---

### Q4: 为什么模式二（ISTORY mini）旋钮切换时需要视觉提示？

**原因**：
- 3-5岁幼儿需要明确的视觉反馈确认操作成功
- 帮助幼儿理解操作与结果的关联
- ISTORY主要依赖音频反馈，ISTORY mini提供视觉+音频双重反馈

---

### Q5: 为什么取消了播放过程中的小夜灯？

**原因**：
- 播放时灯光容易刺眼，影响睡眠质量和听故事体验
- 小夜灯功能保留，关机状态下可通过旋钮或专用按键启用
- 区分播放和关机场景的使用需求

---

### Q6: 为什么两种版本使用不同的密码？

**原因**：
- 防止卡片混用，便于版本管理
- ISTORY密码：`1590`，ISTORY mini密码：`0951`
- 验证码均为 `22`（一致）

---

### Q7: 为什么剧情待选择时不需要自动跳转？

**原因**：
- 用户没睡着可以自己选择，保持交互体验
- 用户睡着了自动跳转会播放音频，容易吵醒
- 选项等待3分钟无操作后自动关机，更适合睡眠场景

---

### Q8: 为什么删除≤20%的电量提示音效？

**原因**：
- 播放音效会打断主音频播放而无法续播
- 红灯闪烁3次已足够提醒用户注意电量
- 优先保证音频播放的连续性

---

### Q9: 为什么等待取消了召唤音频？

**原因**：
- 暂停时等待音效会打断主音频无法续播
- 待机等待音效会干扰小朋友睡觉
- 暂停30分钟或待机3分钟无操作后自动关机，无音效（防止打扰休息）
