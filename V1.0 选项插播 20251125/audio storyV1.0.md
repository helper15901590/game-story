# **冒险故事机：产品需求文档 (PRD) V4.0**

## 1. 产品概述

### 1.0. 公司定位
**互动故事平台**：连接内容创作者与家庭，让故事种类更丰富，给孩子更多选择，提升教育效果；为故事创作者提供收益，激励优质内容产出。

### 1.1. 产品定位与品牌策略
**以"玩"为核心的互动故事设备**，让孩子在娱乐中自然学习，实现"乐中学"的教育目标。

*   **产品品类**: 冒险/互动故事机
*   **品牌名称**: 帽险 (Mào Xiǎn) / 呼咚 (Hū Dōng)
*   **推广策略**: 定义品类 → 品牌占位 → 简化认知 → 品牌即品类

### 1.2. 目标用户与核心价值
*   **核心用户**: 4-8岁儿童
*   **购买决策者**: 重视教育、希望减少孩子屏幕时间的家长
*   **对儿童价值**: 沉浸式互动故事体验，从"被动听"到"主动探索"
*   **对家长价值**: 高质量教育内容平台，解放双手，创造亲子话题

### 1.3. 核心交互设计理念
**冒险机：通过不同冒险选择推动剧情发展，实现间接教育**

*   **产品定位**: 一款冒险机，通过不同的冒险选择剧情发展对应的不同结果对比，来实现间接教育
*   **两大核心功能**:
    *   **选择剧情**: 推动故事发展和趣味，让孩子在冒险中体验不同选择带来的结果
    *   **插播知识**: 辅助对剧情或故事的探索和解读，达到更深层的教育效果
*   **教育理念**: 通过选择创造结果，通过结果实现教育，让孩子在娱乐中自然学习

> *故事机必须是孩子的专属伙伴，而不是家庭中共享的又一块屏幕。* 设备传达的是一种“孩子的独享空间”：他们可以告别平板电脑的干扰，却不必告别乐趣和探索。正如某个故事里的孩子们在抛起玩偶时依旧高喊：“我要看电视！我要看电视！”，这一幕提醒我们，无论是屏幕还是AI玩具，技术只是表象。真正的挑战在于如何引导孩子在真实世界中获得满足感、创造力与情绪价值，这也是家长和产品必须共同承担的长期使命。

### 1.4. 音频设计理念
**双轨音效系统** - 最大化故事沉浸感

*   **冒险搭档**: 陪伴型角色，负责系统提示和知识讲解
*   **故事音效**: 旁白、对话、BGM、环境音效，营造故事世界
*   **音色标准**:
    - 冒险搭档：温暖阳光的少年/少女音
    - 旁白：沉稳磁性的成熟声音
    - 人物对话：多样化、性格鲜明

## 2. 核心用户故事与场景

### 2.1. 一位用户的典型一天 (User Story)
> 晚饭后，5岁的乐乐从书架上选了一张“太空探险”的故事卡。
> 1. 他拿起自己的冒险故事机，**长按多功能旋钮3秒**，熟悉的开机音效响起："冒险家你好，请插入卡片。"，旋钮上的指示灯开始柔和地 **呼吸闪烁**，告诉他"我准备好了"。
> 2. 他想先把音量调好，于是向右旋转旋钮，每转动一格，都伴随着一声清脆的"喂！能听见吗？！"音效，音量越来越大。直到旋钮指示灯 **闪烁了两次红光**，他知道已经无法再调高了。
> 3. 他将故事卡“咔哒”一声 **插入卡槽**，卡片被稳稳固定住。几乎是瞬间，呼吸灯变为 **常亮**，耳边先是响起了一声清脆的提示音：“验证通过，冒险之门已经为你打开！”，随后激昂的太空背景音乐和故事的开场白响起：“你好，小宇航员！勇敢的冒险即将开始……”
> 4. 故事讲到"飞船前方出现了两条布满陨石的航道"，并暂停下来，旋钮指示灯变为 **白色呼吸灯**，告诉他该做选择了。他 **向右旋转旋钮**，听到了第一条航道的简介："左边通往神秘的M78星云…"，介绍音频只播放一次；他再次 **向右旋转**，听到了第二条航道的简介："右边通往闪亮的宝石星系…"。此时，他注意到 **【插播按钮】的指示灯闪亮**，表示有更多关于宝石星系的信息。
> 5. 他对宝石星系充满向往，于是按下了 **【插播按钮】**，插播灯熄灭，开始播放一段关于宝石星系的知识介绍："宝石星系是一个充满珍贵矿物的神秘星域，这里的矿物不仅美丽，还蕴含着巨大的能量，但开采它们需要面对宇宙风暴的挑战…"。这段知识音频帮助他更深入地理解选择宝石星系可能带来的机遇和风险。
> 6. 他满意地 **轻轻按下旋钮** 确认选择。故事立刻沿着他选择的路线继续发展，旋钮指示灯从白色呼吸灯变为 **白色常亮**。
> 7. 故事正讲到精彩之处，妈妈突然喊他喝牛奶。乐乐不愿错过任何细节，便 **轻轻短按了一下旋钮**，故事立刻暂停了，指示灯依然 **常亮**，好像在安静地等待他回来。喝完牛奶，他回到座位上 **再次短按旋钮**，故事无缝地从刚才暂停的地方继续播放。
> 8. 在下一个决策点，故事介绍"飞船的能量核心发出了警报，你是选择紧急迫降，还是冒险穿越虫洞？"。乐乐对虫洞很好奇，在虫洞选项介绍播放时，他看到 **【插播按钮】的指示灯闪亮**，便按下了它，插播灯熄灭，听到了一段关于虫洞的知识介绍："虫洞是连接宇宙不同时空的隧道，穿越虫洞可以瞬间到达遥远的地方，但需要面对未知的风险和时空扭曲的挑战…"。这段知识帮助他理解选择虫洞可能带来的机遇和危险。
> 9. 故事进展有些平缓，乐乐有点迫不及待想知道后面还有什么选择。他想起爸爸教过他的一个"秘密指令"——**长按【多功能旋钮】**，只听"咻...我们到啦！"的音效响起，故事跳过了当前的情节，直接来到了下一个决策点，并自动播放了第一个选项的介绍。
> 10. 故事进入了高潮，突然，他听到了"哎呀！我快没电了，快帮我充电！"的提示音，同时旋钮指示灯 **红色闪烁两次**，然后恢复了常亮。乐乐决定先让故事机休息一下去充电。
> 11. 他 **拔出卡片**，机器提示"冒险之门已关闭，期待再次相见！"后，进入了呼吸灯闪烁的待机状态。他熟练地插上Type-C充电线，因为故事机还在开机状态，所以灯光没有变化。
> 12. 最后，他 **长按旋钮3秒**关机，伴随着"冒险结束了，下次再见！"的关机音效，指示灯变为 **红灯常亮**，他知道故事机正在努力"吃饭"了。第二天早上，他看到指示灯变成了 **绿灯常亮**，就知道故事机已经精力充沛，准备好开始新的冒险了。

### 2.2. 功能简介

#### 2.2.1. 核心功能
- **故事启停 (NFC交互)**
  - **触发**: 将NFC故事卡放置在识别区触发触位开关后，系统立即进行验证。
  - **逻辑**: 验证通过后，自动播放故事开场；拿走卡片则故事立即停止，并进入待机状态。
  - **反馈**: 成功或失败均有明确音效提示，LED灯由“呼吸”变为“常亮”。

- **分支选择 (互动叙事)**
  - **触发**: 当故事主线(M)播放完毕，进入决策点时自动触发。
  - **逻辑**: 旋转【多功能旋钮】可循环收听不同选项(O)的介绍音频；在选项音频播放期间或播放后按下旋钮，即可确认选择并立即中断当前音频，继续播放后续主线。
  - **反馈**: 
    - 主音频停止后，旋钮指示灯变为**白色呼吸灯**，提示等待选择（区别于右侧知识按键的指示灯）。
    - 切换选项时播放对应音频，无额外提示音。
    - 按下旋钮确认选择后，旋钮指示灯从白色呼吸灯变为**白色常亮**。

- **线性播放 (自动衔接/主音频连读)**
  - **触发**: 当一段主线音频(M)播放完毕，且该节点未设置任何分支选项(O)时自动触发。
  - **逻辑**: 系统将根据NFC卡内定义好的播放列表，自动、无缝地开始播放下一段主线音频(M)。支持多个主音频连续播放（如M1跳转到M3，M2也跳转到M3）。
  - **反馈**: 音频连续播放，无额外提示音。

- **知识插播 (情景学习)**
  - **触发**: 在收听选项介绍(O)时，随时可按下【知识按键】。
  - **逻辑**: 按下后，系统将打断选项介绍，并插播与该选项关联的知识音频(K)。知识音频播放完毕后，会进入等待指令状态。在知识音频播放期间，旋转旋钮可立即打断并返回选项介绍。在知识音频播放期间，再次按下插播按键，则重播知识音频（K）。
  - **反馈**: 
    - 主音频播放完毕时，【知识按键】指示灯不亮，等待进入选择状态。
    - 每次切换到有关联知识音频(K)的选项介绍(O)时，【知识按键】指示灯**闪亮**提示。
    - 按下【知识按键】后，指示灯熄灭，开始播放知识音频。
    - 知识音频播放期间，指示灯保持熄灭；播放结束后，如果仍在选项介绍状态，指示灯恢复闪亮。

#### 2.2.2. 辅助功能
- **开关机**
  - **逻辑**: 长按【多功能旋钮】3秒，控制设备电源的开启与关闭。
  - **反馈**: 伴有开/关机音效，LED灯相应亮起或熄灭。

- **播放/暂停**
  - **逻辑**: 在故事主线(M)播放过程中，短按【多功能旋钮】可暂停或继续播放。此操作在选项介绍(O)或知识插播(K)时无效。
  - **反馈**: 音频即时暂停/播放，无额外提示音。

- **音量调节**
  - **逻辑**: 在开机非插卡状态下，旋转【多功能旋钮】，可实时调节系统音量（共10级）。
  - **反馈**: 每调节一级均有音效提示；达到最大或最小音量时，LED灯将快速连续闪烁提示。

- **快进/跳过**
  - **逻辑**: 在故事主线(M)播放中，长按【多功能旋钮】可跳过当前音频的剩余部分，直接跳转到下一个决策点。若后续无决策点，则此操作无效。
  - **反馈**: 伴有专属“跳转”音效。

- **状态提示**
  - **逻辑**: 系统实时监测电池电量及充电状态。
  - **反馈**: 
    - **充电状态**: 充电中为LED红灯常亮；充满后为绿灯常亮。
    - **低电量警告**: 
      - 电量首次低于 **20%** 时，播放充电提示音，且LED进行连续“红色闪烁”。
      - 电量首次低于 **10%** 时，播放关机提示音，LED红灯转为“急促闪烁”，设备将自动关机。

- **自动休眠**
  - **逻辑**: 在待机状态或决策点长时间（3分钟）无任何操作，设备将自动关机以节省电量。
  - **反馈**: 在关机前会分两次（第1、2分钟）播放提示音，提醒用户进行操作。

## 3. 功能与规格详述 (Specifications)

### 3.1. 硬件规格
| 序号 | 硬件组件 | 核心规格/要求 |
| :--- | :--- | :--- |
| 1 | 主控芯片 (MCU) | 16引脚，不外挂Flash。 |
| 2 | 存储 | 32GB TF卡，用于储存所有故事内容及系统音效。 |
| 3 | 多功能旋钮 | **核心交互模块**。支持左/右旋转编码（共10级音量调节）、按下确认、长按3秒开关机。自带三色(红/绿/蓝)LED状态指示灯，支持白色呼吸灯和白色常亮模式用于选项提示。 |
| 4 | 知识按键 | 触觉按键，自带单色(白光偏黄)LED状态指示灯，支持闪亮和熄灭模式用于插播提示。 |
| 5 | Type-C 充电口 | 标准充电功能，充电电流0.5-1A (优选1A)。 |
| 6 | NFC识别芯片 | **模块: RC522mini**。识别 **NTAG216** 型号NFC卡片ID。圆形，直径<2.5cm。芯片要求可加密，并采用动态码校验：MCU首次识别带出厂密码的NFC卡时，会生成一个随机动态码写入NFC空白区，后续每次读取时进行匹配，防止卡片被复制后在其他设备上使用。 |
| 7 | 扬声器（喇叭） | 阻抗4Ω，功率3W。 |
| 8 | 电池 | **刀片式** 锂电池，容量2000mAh，标称电压3.7V（满电4.2V），自带保护电路板。 |

| **第四阶段** | **智能语音互动** | 集成语音识别模块，实现类似Yoto的语音点播、简单问答等功能。 |
| | **耳机输出** | 支持3.5mm耳机输出，扩展使用场景。 |
| | **NFC卡记忆功能** | 通过插拔卡的触位按钮实现故事记忆与读取功能，记忆当前故事音频读取的文件名并写入NFC固定扇区，支持故事进度保存和恢复。 |

## 5. 内容生态框架

本节为故事内容创作提供方向性建议和技术规格约束。

### 5.1. 内容数据结构与规格
- **音频编码**: 采用16进制编码进行音频文件的映射与索引。
- **NFC存储**:
    - **芯片型号**: NTAG216 (888字节)。
    - **数据记录**: 故事的播放逻辑节点数据记录在NFC芯片内。一张卡最多支持255个音频文件（包含M/O/K等所有类型）的索引。
    - **数据烧录**: 卡片数据由产商在出厂时一次性写入并设置为只读，以确保内容安全。
- **故事结构**:
    - **音频总量**: 每个独立的故事总音频数（M+O+K）建议在100-120个之间。
    - **选项限制**: 每个主线音频(M)节点后，最多支持**3个**剧情选项(O)。（从原来的5个减少到3个，以节省NFC容量，可多出一半的NFC容量用于其他数据）
    - **主音频连读**: 支持主音频直接跳转到另一个主音频（如M1跳转到M3，M2也跳转到M3），实现主音频的连续播放，无需经过选项选择。
    - **故事循环**: 支持通过选项从一个较晚的主线节点（如M10）跳转回一个较早的主线节点（如M1），以实现循环或多结局的故事线。
    - **线性播放**: 主线音频(M)节点后，若无剧情选项(O)，可直接指定并跳转至下一个主线音频(M)节点，实现故事的线性叙事。

### 5.1.1. 剧情逻辑设定原则

在内容和剧情逻辑的设定上遵循以下原则：

**1. 改编原著内容的剧情逻辑（主线汇聚型）**
- **适用场景**: 改编经典原著、历史故事等已有固定结局的内容
- **跳转逻辑**: 采用主线跳主线的跳转逻辑
- **设计原则**: 
  - 不同选择对应不同的分支剧情，但最终会汇聚到统一的主线剧情
  - 通过不同路径体验不同过程，但保持故事主线的完整性
- **示例**: 
  - 孙悟空打白骨精时，可选择使用"法术"或"金箍棒"
  - 选择"法术" → 播放法术打败白骨精的剧情(M1) → 跳转到统一主线(M3)
  - 选择"金箍棒" → 播放金箍棒打败白骨精的剧情(M2) → 跳转到统一主线(M3)
  - 两种方式最终都汇聚到"打败了白骨精继续取经"的统一主线剧情
- **优势**: 节省内容工作量，保持原著故事完整性，让孩子体验不同选择带来的不同过程

**2. 原创分支剧情的剧情逻辑（完全分支型）**
- **适用场景**: 原创故事、开放式冒险等需要完全分支发展的内容
- **跳转逻辑**: 不同选择跳转到完全不同的故事剧情，无交集
- **设计原则**: 
  - 不同选择导致故事走向完全不同，形成独立的故事分支
  - 每个分支都有自己完整的故事线和结局
  - 鼓励孩子通过多次体验探索不同的故事可能性
- **示例**: 
  - 小明在森林迷路了，可以选择"走水路"或"走陆路"
  - 选择"走水路" → 进入水上冒险剧情线（M10→M11→M12...→E1）
  - 选择"走陆路" → 进入陆地探险剧情线（M20→M21→M22...→E2）
  - 两条路线完全独立，故事性完全不同，没有交集
- **优势**: 提供丰富的故事可能性，增强探索欲望，提高故事重玩性

**3. 混合型剧情逻辑**
- **适用场景**: 复杂故事结构，既有改编部分也有原创分支
- **设计原则**: 在故事的不同阶段灵活运用上述两种逻辑
  - 改编部分采用主线汇聚型，保持故事框架
  - 原创部分采用完全分支型，增加探索乐趣
- **示例**: 
  - 故事前半段改编《西游记》情节，采用主线汇聚型
  - 故事后半段加入原创冒险，采用完全分支型
  - 形成"经典框架 + 创新探索"的混合结构

**选择建议**:
- **节省内容工作量**: 优先使用主线汇聚型（改编原著）
- **增强探索乐趣**: 优先使用完全分支型（原创冒险）
- **平衡内容与体验**: 根据故事类型和创作资源灵活组合
    
### 5.2. 核心故事类别

#### 5.2.0. 插播(K)使用核心原则
**⚠️ 重要：插播(K)必须与当前选项(O)紧密结合，保持故事沉浸感**

*   **核心原则**: 插播(K)知识必须直接服务于当前正在播放的选项(O)内容，帮助孩子理解该选项的背景、原理、后果或相关知识。插播不应是独立的知识点，而应是选项的自然延伸。
*   **沉浸感要求**: 
  - ✅ **正确示例**: 选项提到"选择穿越虫洞" → 插播解释"什么是虫洞？穿越虫洞可能遇到什么？"（与选项直接相关）
  - ❌ **错误示例**: 选项提到"选择穿越虫洞" → 插播突然讲"太阳系有八大行星..."（与选项无关，破坏沉浸感）
*   **设计检查清单**:
  1. 插播内容是否直接解答当前选项中的疑问？
  2. 插播是否能帮助孩子更好地理解该选项的含义？
  3. 插播是否能增强孩子对该选项的兴趣或帮助做出判断？
  4. 如果移除插播，选项是否仍能独立理解？（如果答案是"否"，说明插播是必要的）
*   **叙事连贯性**: 插播应该像是"冒险搭档"在关键时刻给出的提示和帮助，而非突然跳出故事的"科普时间"，确保孩子始终保持"我在冒险中"的沉浸感。

### 1. 文本剧情模块

#### 1.1. 核心标记定义

| 标记类型 | 标记格式 | 含义说明 |
|---------|---------|---------|
| **M** | M1, M2, M3... | 主线剧情节点 |
| **O** | O1, O2, O3... | 分支选项（每个M节点后出现） |
| **K** | K1, K2, K3... | 知识解读（每个O选项对应一个K） |

#### 1.2. 故事结构

```
M1 (主线剧情1)

```

### 2. NFC编码模块

#### 2.1. 硬件参数

- **芯片型号**：NTAG216（ISO 14443-3A）
- **存储容量**：国产芯片868字节 / 进口芯片888字节
- **扇区地址**：十六进制格式

#### 2.2. 写入流程概览

**目的**：为故事芯片写入的顺序与依赖关系建立一条清晰的流程，避免跨团队协作时出现遗漏或覆写。

1. **读取芯片与记录 UID**：验证当前芯片型号是否为 NTAG216，并备份原始数据（如有）供追溯。
2. **设置/启用密码**：依据 2.7 节的命令写入 E3-E6 扇区，先锁定芯片，保证后续内容仅能由授权人员继续写入。
3. **写入故事元数据**：在扇区 04 写入故事编号与主音频数量（参见 2.5 节），确保 TF 卡文件夹命名与数量校验一致。
4. **写入主线节点数据**：从扇区 05 开始依次写入每个 M 节点的跳转配置（参见 2.6 节），并即时核对跳转逻辑。
5. **二次校验**：重新读取关键扇区（04、05+、E3-E6），确认数据与脚本、音频命名表一致。
6. **按需关闭或保持密码**：若需开放读写，执行 2.7 节的“关闭密码”流程；否则保留密码并记录给量产或售后团队。

#### 2.3. 工具与命令操作

**工具**：NFC TOOLS PRO（Android 应用）

**操作步骤**：
1. 打开 NFC TOOLS PRO。
2. 进入 **其他** → **先进的 NFC 命令**。
3. 点击 **放大镜** 图标，选择 **TAG TYPE2（ISO14443-3A）**。
4. 选择 **Write4bytes**（写入 4 字节）。
5. 根据 2.5、2.6、2.7 节的内容，依次输入对应命令。

**写入格式**：
- 格式：`A2:XX:BB:BB:BB:BB`
  - `A2`：写入命令（固定不变）
  - `XX`：写入块编号（十六进制，可变，如 `04` 表示扇区 04）
  - `BB:BB:BB:BB`：当前扇区的第 1、2、3、4 个块（Block）的数值（十六进制）
- **连续写入**：可以连续写入不同的块，用英文字符 `,` 间隔
  - 示例：`A2:04:10:01:0A:05,A2:05:03:02:03:04`

**命令说明**：
- `A2`：写入命令（用于写入数据到指定扇区）
- `1B`：密码验证命令（用于验证密码后执行后续操作）

**注意事项**：
- 每次写入操作覆盖 1 个块（4 字节），请谨慎确认数据。
- 写入顺序应遵循 2.2 节的流程，避免在未启用密码前写入核心内容。
- 写入前请确保 NFC 芯片已正确放置在设备上，写入后立即读取校验。

**结果**：按上述步骤写入后，NFC 芯片包含完整且受控的故事结构数据，设备即可根据编码规则播放音频。

#### 2.4. 扇区布局

| 扇区地址 | 对应M节点 | 用途 |
|---------|---------|------|
| `00-03` | - | 厂家信息区（UID等系统信息） |
| `04` | - | 故事元数据区（故事编号、主音频数量） |
| `05+` | M1+ | 主线故事数据区（每个M节点占用1个扇区，4个块/Block） |
| `E3-E6` | - | 密码区和验证码区 |

#### 2.5. 扇区04：故事元数据区

**原因**：设备需要知道这是哪个故事（故事编号），以及这个故事有多少个主音频文件，用于验证TF卡中的音频文件是否完整。

| 块（Block） | 字段 | 格式 | 说明 |
|------|------|------|------|
| 1 | 故事编号高位 | 十进制 | 故事编号的高位部分（仅用于与低位做**前后拼接**，不做加减或进位计算） |
| 2 | 故事编号低位 | 十进制 | 故事编号的低位部分（仅用于与高位做**前后拼接**，不做加减或进位计算） |
| 3 | 主音频数量高位 | 十六进制 | 记录主音频数量的高位字节（含E类结局音频，最大不超过`FF`） |
| 4 | 主音频数量低位 | 十六进制 | 理论上用于记录主音频数量的低位字节，但由于当前故事的主音频总数不足`0x100`，实际应用中**恒为`00`** |

**写入过程**：
- 将故事编号拆分为高位和低位两部分，分别写入块1和块2
- 统计该故事所有主音频文件数量（含E类结局音频），将数量转换为十六进制写入块3（高位字节）
- 由于扇区内主线M节点数量有限，主音频总数最大不超过`0xFF`，因此块4（低位字节）固定写入`00`
- 写入命令示例：`A2:04:10:01:14:00`（故事编号1001，主音频数量0x14 = 十进制20，对应块3=`14`，块4=`00`）

**示例**：
- NFC中故事编号：高位`10` + 低位`01` → 设备按字符串前后拼接为 `1001`
- TF卡中文件夹名：在前面再补一位固定前缀`0`，最终为 `01001`，用于实际的故事文件夹匹配
- 主音频数量：20 = 十六进制`14`，写入块3，块4固定为`00`

**结果**：设备读取NFC时，能够识别故事编号，并根据块3中的值验证主音频文件数量；块4作为预留的低位字节，在当前扇区数量范围内始终为`00`。（故事编号与TF卡故事文件夹的对应关系见 3.1 节）

#### 2.6. 扇区05+：主线故事数据区

**原因**：设备需要知道每个M节点有多少个选项，以及用户选择每个选项后应该跳转到哪个M节点，这样才能实现交互式故事播放。

**数据结构**：每个M节点占用1个扇区（4个块/Block），所有数据均为十六进制。

| 块（Block） | 字段 | 取值范围 | 说明 |
|------|------|---------|------|
| 1 | 选项音频数量 | `00-03` | 当前M节点包含的选项数量（O1-O3）或 0 个 |
| 2 | O1跳转目标 | `00-FF` | O1选项跳转的M节点编号（M1=`01`, M2=`02`...，无则`00`） |
| 3 | O2跳转目标 | `00-FF` | O2选项跳转的M节点编号（M1=`01`, M2=`02`...，无则`00`） |
| 4 | O3跳转目标 | `00-FF` | O3选项跳转的M节点编号（M1=`01`, M2=`02`...，无则`00`） |

**M节点编号映射**：M编号 = 十六进制值（M1=`01`, M2=`02`, M10=`0A`, M11=`0B`, M17=`11`...）

**编码规则**：
- 所有数据均为十六进制格式（仅故事编号使用十进制）
- `00` 表示选项不存在或无跳转
- 支持循环跳转（如O2跳转回M1，记录为`01`）

**写入过程**：
- M1节点写入扇区05：`A2:05:03:02:03:04`（3个选项，分别跳转到M2、M3、M4）
- M2节点写入扇区06：`A2:06:02:05:01:00`（2个选项，分别跳转到M5、M1）
- 每个M节点按顺序占用下一个扇区（M1→扇区05，M2→扇区06，M3→扇区07...）

**示例**：
- **M1节点（扇区05，3个选项）**：`03 02 03 04` → 3个选项，分别跳转到M2、M3、M4
- **M2节点（扇区06，2个选项）**：`02 05 01 00` → 2个选项，分别跳转到M5、M1

**特殊情况**：当块1为`00`时（无选项），块2含义：
- **非`00`的M类编号**：主音频直接跳转到另一个主音频（主音频连读）——逻辑上仍视为M类主音频
  - 示例：`00 0B 00 00` → M10主音频播放完后直接跳转到M11
  - **原因**：某些剧情节点不需要用户选择，自动连续播放
  - **结果**：播放完当前主音频后，自动播放下一个主音频，不等待用户选择
- **`00`**：E类结束音频（逻辑上视为M类结局节点），播完后播放系统音效`0011.mp3`（剧终）
  - 示例：`00 00 00 00` → 所在扇区的第1~4块均为`00`时，表示该主音频为E类结束音频
  - **原因**：通过`00 00 00 00`在NFC中标记“终局节点”，设备据此判断故事已结束
  - **结果**：播放完该E类结束音频后，自动播放系统"剧终"提示音`0011.mp3`，故事结束；此类结局音频在播放过程中不可跳过

**结果**：设备读取NFC后，能够根据用户选择的选项，准确跳转到对应的M节点，实现分支剧情的交互式播放。

#### 2.7. 扇区E3-E6：密码与验码区

| 扇区地址 | 功能 | 数据内容（十六进制） | 说明 |
|---------|------|------------------|------|
| `E3` | 密码命令 | `04 00 00 00` | 密码操作命令字（最后 1 字节 `00`=启用密码、`FF`=关闭密码） |
| `E4` | 密码错误机制 | `00 05 00 00` | 试错次数限制（示例为 5 次） |
| `E5` | 密码保存区域 | `0x31 0x35 0x39 0x30` | NFC 密码：1590（ASCII 编码） |
| `E6` | 验证码区域 | `0x32 0x32 0x00 0x00` | 验证码：22（ASCII 编码） |

**说明**：
- E5、E6 采用 ASCII 编码，便于与工具界面直接对应。
- E4 的第二个字节指定允许的最大输错次数，和量产设置一致即可。
- E3 的最后一个字节控制密码开关：`00` 表示启用密码保护，`FF` 表示关闭密码保护；其余字节遵循方案商推荐值，避免随意修改。

**设置密码操作（国产 NTAG216）**：

**目的**：保护 NFC 数据不被篡改或误写，是 2.2 节流程的首要步骤。

**写入命令**：
```
A2:E3:04:00:00:00,A2:E4:00:05:00:00,A2:E5:31:35:39:30,A2:E6:32:32:00:00
```
- 一次性写入 E3（启用密码，即最后一字节为 `00`）、E4（试错次数 5 次）、E5（密码 1590 的 ASCII）、E6（验证码 22 的 ASCII）。

**结果**：芯片启用密码保护，后续写入需先通过 `1B` 命令验证密码，最多允许输错 5 次。

**关闭密码操作（国产 NTAG216）**：

**目的**：在量产调试或售后维护时允许自由读写，通常在完成所有写入后执行。

**写入命令（含重新写入已烧录故事的芯片）**：
```
1B:31:35:39:30,A2:E3:04:00:00:FF,A2:E4:00:05:00:00,A2:E5:00:00:00:00,A2:E6:00:00:00:00
```
- 首先使用 `1B` 命令验证当前密码（示例为 1590）。
- 依次写入 E3（关闭密码，最后字节改为 `FF`）、E4、E5、E6，将密码与验证码清空。

**结果**：芯片恢复为无密码状态，可直接读写所有扇区。若需重新保护，请回到本节“设置密码操作”。

### 3. TF音频命名模块

**音频格式要求**：MP3/WAV（推荐MP3），8kHz-44.1kHz采样率，单声道，8kbps-320kbps码率

#### 3.1. 文件夹命名规则

- **系统文件夹**：`SYSTE`（全大写），存放系统相关文件
- **故事文件夹**：`00000`-`99999`（5位十进制数字，**首位固定为`0`，后4位与NFC扇区04中的故事编号（高位+低位拼接）一一对应**），存放故事音频文件

#### 3.2. 系统文件夹音频文件命名

系统文件夹`SYSTE`中的音频文件使用4位数字编号（`0001`-`0011`）：

| 文件命名 | 应用场景 | 说明 |
|---------|---------|---------|
| `0001.mp3` | 开机 | 设备启动提示音 |
| `0002.mp3` | 关机 | 设备关闭提示音 |
| `0003.mp3` | 音量调节 | 音量调整提示音 |
| `0004.mp3` | 读卡错误 | TF卡读取失败提示 |
| `0005.mp3` | 读卡正确 | TF卡读取成功提示 |
| `0006.mp3` | 拔卡 | TF卡移除提示 |
| `0007.mp3` | 跳过主音频 | 跳过当前主音频提示 |
| `0008.mp3` | 等待1&2分钟 | 等待提示 |
| `0009.mp3` | 电量≤20% | 低电量提示 |
| `0010.mp3` | 电量≤10% | 极低电量提示 |
| `0011.mp3` | 剧终 | 故事播放结束提示 |

#### 3.3. 故事音频文件命名规则

| 音频类型 | 命名格式 | 编号规则 | 示例 |
|---------|---------|---------|------|
| **M类主音频 / E类结局音频** | 4位数字 | 前3位为M节点编号 + 最后1位固定`0` | M1 → `0010.mp3`（若为结局则在NFC中以`00 00 00 00`标记为E类） |
| **O类选项音频** | 4位数字 | M编号前3位 + 第四位`1-3` | M1的O1 → `0011.mp3`，O2 → `0012.mp3` |
| **K类知识解读** | 4位（3位数字+1位字母） | M编号前3位 + 第四位`A-C` | M1的K1 → `001A.mp3`，K2 → `001B.mp3` |

**编号对应关系**：
- M/E类：E类结束音频在TF卡中与所属M节点的主音频共用同一命名规则（即“E视为M”）
- O类：O1→1, O2→2, O3→3
- K类：K1→A, K2→B, K3→C

**文件组织**：按M节点分组，顺序为 M类主音频 → O类选项音频（按编号）→ K类知识解读音频（按编号）

**示例**（故事文件夹`01001/`）：
- M1节点（3个选项）：`0010, 0011, 0012, 0013, 001A, 001B, 001C`
- M2节点（2个选项）：`0020, 0021, 0022, 002A, 002B`
